## goal

Lock how recording is **referenced and lifecycle-stamped** in DB, and the behavioural rule that stop is mandatory on Ending — without putting PCM in Postgres.

## in_scope

### Storage choice (planning)

**V1:** Keep `session.recording_ref` as the pointer; **add** lifecycle columns on `session` (expand):

| Column | Type | Meaning |
|---|---|---|
| `recording_ref` | TEXT | Existing — opaque ref / relative path id |
| `recording_started_at` | TIMESTAMPTZ NULL | When recorder started |
| `recording_stopped_at` | TIMESTAMPTZ NULL | When stop completed |
| `recording_stop_reason` | TEXT NOT NULL DEFAULT '' | Closed reasons below |
| `recording_bytes` | BIGINT NULL | Optional size after stop |

Alternative (rejected for V1 unless owner overrides): separate `recording` table — defer to reduce joins.

### `recording_stop_reason` closed vocabulary

| Value | Meaning |
|---|---|
| `` (empty) | Not stopped yet |
| `session_ending` | Normal Ending path |
| `session_completed` | Stopped as part of complete |
| `session_failed` | Stopped on failure path |
| `orphan_reaper` | Ops/reaper closed leaked recorder (must exist as concept) |
| `manual` | Explicit ops stop |

### Behavioural rules (bind runtime later; schema supports them)

1. On transition to Ending: **must** request stop; await close; set `recording_stopped_at`.  
2. WebSocket teardown must not skip stop ([04](../04_LIVE_TURN_MACHINE.md) tool settle note analog).  
3. If process crash: reaper uses `recording_started_at IS NOT NULL AND recording_stopped_at IS NULL` after session terminal.  
4. PCM only on disk/object store keyed by `recording_ref`.
