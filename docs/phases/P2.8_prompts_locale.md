## goal

Lock how `prompt_ref` resolves to per-locale text for a published flow version.

## in_scope

### V1 storage decision

**Embedded** in `flow_draft.doc` / `flow_version.doc` under key `prompts`:

```text
prompts: {
  "<prompt_ref>": {
    "<locale>": "<text>",
    ...
  },
  ...
}
```

| Rule | Detail |
|---|---|
| Locale keys | BCP-47 style used by Talk allowlist (e.g. `en-IN`, `hi-IN`) |
| Missing locale at runtime | Fallback order: `active_language` → flow default locale → fail closed (no silent English invent) — **default locale** field on envelope: `default_locale` TEXT required at publish |
| Versioning | Immutable with `flow_version`; edit only via new draft publish |
| Separate `flow_prompt` table | **Not V1** — revisit if admin UX needs SQL search |

### Reserved / conventional `prompt_ref` examples (not exhaustive product copy)

| Ref | Typical use |
|---|---|
| `welcome` | Entry/Speak welcome |
| `closing_transfer` | Tool transfer closing |
| `closing_hangup` | Tool hangup closing |
| `repair_unclear` | Listen repair |
| `silence_nudge_1` | Silence policy |

Nodes reference refs; they do not inline multi-locale blobs on the node (single `prompt_ref` field).

## out_scope

- TTS SSML authoring  
- Auto-translate pipeline  
- Storing audio prompt clips in DB  

## forbidden

- Per-locale **duplicate graphs**.  
- Updating `flow_version.doc.prompts` in place.  

## exit_criteria

- Embedded map shape + `default_locale` + fallback rules Locked.  

## edge_cases

1. Locale in allowlist but missing prompt text → fail closed for that Speak.  
2. Mid-call language switch → subsequent prompts use new `active_language`.
