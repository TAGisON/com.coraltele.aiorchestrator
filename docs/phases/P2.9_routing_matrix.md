## goal

Lock how intent → owner/target/number/action is stored per published flow version.

## in_scope

### V1 storage decision (Locked)

**Embedded** array `matrix` inside flow document (draft + immutable publish). No separate `flow_matrix_row` table for V1.

### Row fields (each element) — Locked

| Field | Type | Required | Notes |
|---|---|---|---|
| `intent` | string | yes | Match key from ListenChoice / edge `matrix_intent`; unique within doc |
| `owner` | string | yes | Human label (screen / TTS name) |
| `target` | string | yes | Queue/label id |
| `number` | string | yes if `action=transfer` | Destination — **admin-authored only**; never LLM-written at runtime |
| `action` | string | yes | Closed V1: `transfer` (hangup Tools do not use matrix rows) |
| `disposition_code` | string | recommended | Must be a P2.6 allowlisted code when set (e.g. `transferred_sales`) |

Example intents (coral-xfer class — **examples only**, not schema enums): `sales`, `corporate`, `support`.

### Resolution at Tool ARM (Locked)

```text
edge.matrix_intent or node config
  → lookup matrix row by intent on pinned flow_version.doc
  → freeze number/owner/target (+ disposition_code) into tool params
  → never ask LLM for dial string
```

### Publish validation (Locked)

- Every Tool node with `tool=transfer` must reference an intent that exists in `matrix` with non-empty `number`.  
- Duplicate `intent` keys in one doc → reject publish.  
- If `disposition_code` set → must be in P2.6 `final` allowlist.  
- Empty `matrix` + any transfer Tool → reject publish (P2.7 edge case).  

## out_scope

- Separate SQL `flow_matrix_row` table (optional later)  
- Runtime ACD queries replacing matrix  
- LLM inventing numbers  
- Authoring flow CREATE DDL (P2.7 plan)  

## forbidden

- Storing matrix only in mutable session metadata.  
- Reading dial numbers from old `desk` tables after cutover.  
- Free-text dial from LLM or STT as SoT.  

## exit_criteria

- [x] Row field table + ARM resolution + publish checks Locked.  
- [x] No separate matrix SQL table for V1.  
- [x] No DDL authored in this phase.  

## migration_plan_note

**None.** Matrix lives in JSON inside `flow_draft` / `flow_version` (P2.7 DDL wave).

## edge_cases

1. Intent not in the three named dispositions → use row `disposition_code` or default `transferred_other`.  
2. Hangup Tool — no matrix row required.  
3. Missing matrix row at ARM time → fail closed (`tool.failed` / `system_failure`); do not invent number.
