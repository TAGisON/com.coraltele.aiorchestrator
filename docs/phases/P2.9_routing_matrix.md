## goal

Lock how intent → owner/target/number/action is stored per published flow version.

## in_scope

### V1 storage decision

**Embedded** array `matrix` inside flow document (draft + immutable publish).

### Row fields (each element)

| Field | Type | Required | Notes |
|---|---|---|---|
| `intent` | string | yes | Match key from ListenChoice / edge `matrix_intent` |
| `owner` | string | yes | Human label (screen / TTS name) |
| `target` | string | yes | Queue/label id |
| `number` | string | yes if action=transfer | Destination for edge transfer — **admin-authored only** |
| `action` | string | yes | `transfer` \| (future: others); V1 transfer rows |
| `disposition_code` | string | recommended | Maps to P2.6 code e.g. `transferred_sales` |

### Resolution at Tool ARM

```text
edge.matrix_intent or node config
  → lookup matrix row by intent on pinned flow_version.doc
  → freeze number/owner/target into tool params
  → never ask LLM for dial string
```

### Publish validation

- Every Tool node with `tool=transfer` must reference an intent that exists in `matrix` with non-empty `number`.  
- Duplicate `intent` keys in one doc → reject publish.

## out_scope

- Separate SQL `flow_matrix_row` table (optional later)  
- Runtime ACD queries replacing matrix  
- LLM inventing numbers  

## forbidden

- Storing matrix only in mutable session metadata.  
- Reading dial numbers from old `desk` tables after cutover.  

## exit_criteria

- Row field table + ARM resolution + publish checks Locked.  

## edge_cases

1. `transferred_other` when intent not in the three named dispositions — use row `disposition_code` or default `transferred_other`.  
2. Hangup Tool — no matrix row required.  

## verification

Owner review vs coral-xfer intents (sales/corporate/support) as example rows — examples only, not hard-coded in schema.

## rollback

Planning only.
