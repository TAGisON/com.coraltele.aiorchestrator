## goal

Design **new** binding entities so Inform (and later CRM skills) reference external knowledge without adopting old `kb_*` schema.

## in_scope

### Entity: `binding` (Locked)

Tenant-scoped registry of external capabilities.

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | Opaque |
| `tenant_id` | TEXT NOT NULL | |
| `kind` | TEXT NOT NULL | Closed V1: `knowledge` \| `crm` (`crm` unused at runtime OK) |
| `name` | TEXT NOT NULL | Display |
| `config` | JSONB NOT NULL | Kind-specific; **no secrets** (refs to `gateway_credentials` by `gateway_id` if needed) |
| `status` | TEXT NOT NULL DEFAULT `'active'` | Closed: `active` \| `disabled` |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

Index: `(tenant_id, kind)`.

### Knowledge `config` shape (V1 Locked)

| Approach | V1 decision |
|---|---|
| Port old chunk tables | **Forbidden** (OD-08-4) |
| Inline FAQ corpus in config | Allowed for **thin** FAQ: `config.mode = "inline_faq"`, `config.entries = [{id, locales, text/questions}]` — size soft-cap at coding phase |
| HTTP retrieve | `config.mode = "http_retrieve"`, `config.gateway_id`, endpoint path in config — credentials via `gateway_credentials` |
| Upload/blob KB product | **Out of V1** |

Closed `config.mode` for `kind=knowledge`: `inline_faq` \| `http_retrieve`.

### Flow reference (Locked)

- `flow_version.doc.binding_refs`: string array of `binding.id`  
- Inform node: `binding_ref` must be in that array and resolve to `kind=knowledge`  
- Missing/disabled binding → Inform fails closed (repair edge), no invent  

### Live lookup vs snapshot (Locked — edge case 1)

Inform uses **live `binding` row by id** at runtime (fail if missing/`disabled`). Disabling a binding breaks live calls that reference it — acceptable for V1 thin FAQ. Snapshot-into-`flow_version` deferred unless a later OD requires pin stability.
