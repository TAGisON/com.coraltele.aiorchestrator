## goal

Design **new** binding entities so Inform (and later CRM skills) reference external knowledge without adopting old `kb_*` schema.

## in_scope

### Entity: `binding`

Tenant-scoped registry of external capabilities.

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | Opaque |
| `tenant_id` | TEXT NOT NULL | |
| `kind` | TEXT NOT NULL | Closed V1: `knowledge` \| `crm` (crm unused at runtime OK) |
| `name` | TEXT NOT NULL | Display |
| `config` | JSONB NOT NULL | Kind-specific; **no secrets** (refs to `gateway_credentials` by gateway_id if needed) |
| `status` | TEXT NOT NULL DEFAULT `'active'` | `active` \| `disabled` |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

Index: `(tenant_id, kind)`.

### Knowledge `config` shape (V1)

| Approach | V1 decision |
|---|---|
| Port old chunk tables | **Forbidden** |
| Inline FAQ corpus in config | Allowed for **thin** FAQ: `config.mode = "inline_faq"`, `config.entries = [{id, locales, text/questions}]` — size soft-cap documented at coding phase |
| HTTP retrieve | `config.mode = "http_retrieve"`, `config.gateway_id`, endpoint path in config — credentials via gateway_credentials |
| Upload/blob KB product | **Out of V1** |

### Flow reference

- `flow_version.doc.binding_refs`: string array of `binding.id`  
- Inform node: `binding_ref` must be in that array and kind=`knowledge`  
- Missing/disabled binding → Inform fails closed (repair edge), no invent  

### Old `kb_*` policy

| Item | Policy |
|---|---|
| New writes after P1 | None (frozen) |
| Content migration to inline_faq | **Not automatic**; manual republish if needed |
| At P2.13 | DROP `kb_document`, `kb_chunk` |
| `internal/control/kb.go` | Remove/replace in a **runtime/control L3 after** this lock — not this schema phase’s code |

### CRM

- `kind=crm` rows may exist as stubs; **no V1 runtime requirement** to call them ([01](../01_VISION_AND_SCOPE.md) Next).  

## out_scope

- Shipping production FAQ quality pack  
- Vector DB  
- Implementing Inform runtime  

## forbidden

- “Keep kb_* and wire Inform to them for speed.”  
- Secrets inside `binding.config`.  

## exit_criteria

- `binding` table Locked.  
- Knowledge config modes Locked.  
- Retirement note for `kb_*` ready for P2.13.  

## edge_cases

1. Flow published with binding_ref then binding disabled → live pinned version still has old config snapshot? **Decision:** Inform uses **live binding row** by id (fail if disabled) — simpler ops; document that disabling breaks live calls using it. Alternative (reject): snapshot binding into flow_version — **V1 choose live lookup by id** for thin FAQ; revisit if needed.  
2. Inline FAQ large payload — soft-cap in coding principles.
