## Principles (locked for planning)

### P2.0-P1 — Identity and tenancy

- Every multi-tenant row carries `tenant_id` (TEXT) unless it is strictly session-scoped and reachable only via `session_id` that already implies tenant.  
- Public IDs for sessions, flows, credentials keys: opaque TEXT (ULID/UUID string) — no sequential guessable external IDs for sessions.  
- Internal ordering may use `BIGSERIAL` / `seq INT` **within** a session (transcript/audit).

### P2.0-P2 — Time

- All timestamps `TIMESTAMPTZ` UTC.  
- Append-only evidence rows: `created_at` set once; **no UPDATE** of event body after insert (see P2.0-P4).  

### P2.0-P3 — Session is the live call spine

- One `session` row per live (or completed) call attempt the orch owns.  
- Session points at **published flow version** (after P2.7 exists); until then may still reference `profile_id`/`profile_version` during transition — transition mapping is explicit in P2.2, not silent dual-write forever.  
- Terminal session states are closed vocabulary (P2.2 locks list).  

### P2.0-P4 — Evidence is append-only

Applies to transcript events and audit events:

- Insert only; corrections = **new** event (e.g. redact marker), never rewrite history in place.  
- Transcript must support **continuous** events ([04](../04_LIVE_TURN_MACHINE.md) § Transcript), not only neat user/assistant pairs ([02](../02_CURRENT_STATE.md)).  
- Every user STT final stores `actionable` boolean + `reason` when not actionable.  

### P2.0-P5 — Audit vocabulary is closed for V1 emitters

- Runtime emits only allowlisted `event_type` strings (P2.4 locks list).  
- Unknown types in old rows may exist; new code must not invent unchecked strings.  
- Tool lifecycle must be representable: armed / executed / failed (align with [04](../04_LIVE_TURN_MACHINE.md) tool lock).  

### P2.0-P6 — Recording metadata ≠ PCM

- DB holds **refs + lifecycle** (`recording_ref`, started_at, stopped_at, stop_reason, byte_size optional).  
- PCM/WAV lives on filesystem/object store outside Postgres.  
- **Hard rule:** recording **must stop** when the call leg/session reaches Ending ([02](../02_CURRENT_STATE.md), [04](../04_LIVE_TURN_MACHINE.md)). Schema must be able to record `stopped_at` and detect “never stopped” for ops.  

### P2.0-P7 — Disposition is local V1

- Store final disposition on the session (table or columns — P2.6 chooses).  
- Values are closed vocabulary aligned with tool/graph outcomes (transfer targets, hangup reasons, out_of_scope, system_failure, …).  
- CRM push of disposition is **out of V1** ([01](../01_VISION_AND_SCOPE.md)).  
- Old tags `resolved`/`unresolved`/`escalated` are **not** assumed sufficient; P2.6 replaces with CC-oriented list.

### P2.0-P8 — Config versioning (flow)

- Authored graph is **draft** mutable; **published** version immutable ([03](../03_BRAIN_AND_GRAPH.md)).  
- Live sessions pin a published version id; mid-call publish does not mutate pinned doc.  
- New tables use `flow_*` (or locked companions) — never `desk_*` (OD-08-3). Detailed in P2.7+.  

### P2.0-P9 — Secrets

- API keys only in `gateway_credentials` (or successor named in P2.1).  
- Never in `flow_*` JSON, audit payloads, or git.  
- Docs/commits must not paste secrets ([AGENTS.md](../../AGENTS.md)).  

### P2.0-P10 — Expand/contract migrations

- Additive columns first; backfill; switch readers; then drop obsolete (contract).  
- Never edit applied migration files under `internal/store/migrations/` / `migrations/` history.  
- One **concern** per new migration file (e.g. “add transcript actionable columns” ≠ “drop desk + create flow” together without sequenced steps and rollback notes).  
- P2.14 locks numbering/CI; this principle forbids bulk regardless.

### P2.0-P11 — Knowledge freeze

- `kb_*` receive **no new features** after P1; P2.10 redesigns bindings; P2.13 DROPs old tables (OD-08-4).  
- Inform V1 must not be planned as “read kb_chunk.”  

### P2.0-P12 — No silent dual brain

- After P2.7 publish model exists, orch must not keep writing desk documents as the live dialogue source.  
- Transition window (if any) is named in P2.2/P2.7 exit criteria with an end date/phase — not indefinite.
