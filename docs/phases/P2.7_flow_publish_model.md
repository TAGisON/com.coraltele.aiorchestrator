## in_scope

### Storage strategy (V1 Locked)

| Choice | Decision |
|---|---|
| Registry + draft + version tables | **Yes** — mirrors publish discipline; new names `flow_*` only |
| Normalized `flow_node` / `flow_edge` SQL rows | **No for V1** — nodes/edges live inside published **JSONB document** |

Rationale: one pin per session (`flow_id`+`flow_version`); immutability of published blob; admin UI can evolve document without multi-table migrations every node edit.

### Publish rules (Locked)

1. Validate envelope (`schema_id`, node types, edge endpoints exist, Entry exists, `entry_node_id` points at Entry).  
2. Insert `flow_version` with next version; never UPDATE `doc`.  
3. Set `flow.current_version` / `status=published`.  
4. Live sessions already pinned keep old version (mid-call publish does not mutate pin).  

### Transition end — no silent dual brain (P2.0-P12) — Locked

| Rule | Detail |
|---|---|
| Desk docs | Must not be written as live dialogue source (already purged post-P1). |
| Profile vs flow pin | `session.profile_id`/`profile_version` remain **Transition** until graph runtime requires `flow_id`+`flow_version` for **new** live sessions. |
| Named end | Dual-pin window ends at the **first runtime L3** that refuses new live sessions without a published flow pin (cite this file + that phase). Not indefinite. Contract DROP of profile FK on session is a later migrate after that runtime cutover — not P2.7. |

## edge_cases

1. Empty matrix + Tool transfer node → publish must fail closed.  
2. Inform node without `binding_ref` → **fail publish**.  
3. Unpublished flow (`current_version=0` / not `published`) → cannot pin on new live session.  
4. `schema_id` ≠ `coral.flow.v1` → reject publish/load.
