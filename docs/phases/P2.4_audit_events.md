### Current code inventory (tolerate in readers — do not use for new emitters)

From `store.Audit*` + observe/control (2026-09-04):

| Current `event_type` | Disposition |
|---|---|
| `session.started` | **Transition** → prefer `session.created` / `session.live` |
| `session.terminal` | **Transition** → `session.completed` \| `cancelled` \| `failed` (use payload/`state`) |
| `turn.completed` | **Transition** → `turn.state` or drop if redundant with transcript |
| `skill.executed` | **Transition** → `tool.executed` |
| `barge_in` | **Transition** — optional keep as ops signal or fold into `turn.state` |
| `error` | **Transition** → prefer `session.failed` / `tool.failed` with reason |
| `disposition.suggestion` | Keep emitting until P2.6 locks disposition evidence; then revisit |
| `listen.final` / `listen.suppressed` | Prefer transcript `user_final` + actionable; audit optional |
| `speak.prompt` | Optional ops; not required on V1 allowlist |

**Deprecated (do not emit after P1.12):** `desk.end`, `desk.transfer`, any `desk.*`.

Readers **must tolerate** unknown/legacy types (P2.0-P5). Runtime alignment of constants/emitters is a later phase citing this file — **not** silent invent in store migrations.

### Payload rules

- No `api_key`, tokens, raw PCM, full WAV paths beyond `recording_ref` id.  
- Tool params may include destination number (operational need) — still not LLM-invented at write time.  
- Prefer small JSON; no full transcript dumps.
