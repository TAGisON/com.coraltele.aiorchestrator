### Session `state` closed vocabulary (V1 Locked = code inventory)

Exact strings from `internal/store/store.go` (do not invent lowercase drift):

| Value | Meaning |
|---|---|
| `Created` | Row exists; not yet attached/running |
| `Attached` | Edge/session attached |
| `Running` | Media/talk active |
| `Draining` | Teardown / stop in progress (maps to Ending behaviour in [04](../04_LIVE_TURN_MACHINE.md)) |
| `Completed` | Clean end |
| `Cancelled` | Caller/edge cancel path |
| `Failed` | System failure end |

New emitters must use only this allowlist (P2.0-P5 spirit for session state). Runtime may refine mapping to product “Ending” language later without renaming stored values without an expand/contract phase.

- Dual-writing desk id onto session as dialogue source after P2.7.  
- Storing full transcript or PCM inside `metadata`.  
- Premature P2.2-only migration that invents `flow_*` pins before P2.7.  
- Changing `state` strings away from code inventory without a dedicated expand/contract plan.

## migration_plan_note

**None required in P2.2.** Session shape already includes language columns and `gateway_binding`. Additive `flow_id` / `flow_version` / optional `turn_state` wait for **P2.7** (and expand/contract per P2.0-P10). Do not edit applied `001`/`004`/`005` history.

## edge_cases

1. Session without flow pin during post-P1 dialogue-offline era — allowed (`flow_*` NULL until P2.7+).  
2. Recording_ref set but stop never recorded — P2.5.  
3. `tenant_id` NULL on legacy rows — retain; new writers should set tenant.
