## goal

Lock how migrations are numbered, applied in test/CI, and failed — so Implementers cannot invent ad-hoc SQL.

## in_scope — rules

### P2.14-R1 Numbering

- New files only under the repo’s **canonical** migration path used by `store.Open` (today: `internal/store/migrations/`).  
- Do not fork divergent copies in root `migrations/` without a single SoT decision — **SoT = `internal/store/migrations/`**; root copies if present must not be a second writer (cleanup note for coding phase).  
- Filenames: monotonic `NNN_snake_description.sql` continuing after highest existing N (today through `009_…`).  
- Never reuse N; never edit applied files.

### P2.14-R2 One concern

- One migration file = one concern (create flow family **or** alter transcript **or** drop desk family — not combined).  

### P2.14-R3 Apply

- App boot / `store.Open` applies pending migrations transactionally per file.  
- Failure → process must **refuse to serve** if `database.require=true`; lab memory mode unaffected.

### P2.14-R4 CI (minimum)

Until doc 11 expands:

| Check | Required |
|---|---|
| `go test ./internal/store/...` including migrate tests | Yes at L4 for any migration PR |
| Apply all migrations on empty Postgres in CI | Yes when CI exists (doc 11); until then manual lab checklist on migration PRs |
| Forbidden: merge migration that fails empty apply | Yes |

### P2.14-R5 Expand/contract

- Prefer additive NULLable columns → backfill → switch readers → DROP/NOT NULL in later file.  

### P2.14-R6 Secrets

- Migrations must not insert real API keys.  

### P2.14-R7 Dual path

- No migration may reintroduce `desk_*` table creates.  

## out_scope

- Full CI matrix OS/arch (doc 11)  
- Blue-green deploy topology  

## forbidden

- Hand-applying SQL on prod without migration file.  
- `IF NOT EXISTS` create of obsolete desk tables “for safety.”  

## exit_criteria

- Rules R1–R7 Locked for Implementer skill citation.  

## edge_cases

1. Two agents land migrations with same N — reject; renumber before merge.  
2. Long LOCK on DROP — schedule maintenance; note in phase summary at L4.
