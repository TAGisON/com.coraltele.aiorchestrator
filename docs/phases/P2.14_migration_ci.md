## goal

Lock how migrations are numbered, applied in test/CI, and failed — so Implementers cannot invent ad-hoc SQL.

## in_scope — rules (Locked)

### P2.14-R1 Numbering

| Rule | Locked value |
|---|---|
| **SoT path** | `internal/store/migrations/` only (`//go:embed` in `store.ApplyMigrations`) |
| **Root `migrations/`** | **Not a writer.** Inventory 2026-09-05: incomplete mirror (has `001`–`003`, `006`, `007` only; missing `004`, `005`, `008`, `009`). Do not author new SQL there. Cleanup (delete or freeze-as-historical-copy) is a later coding chore — not this planning L4. |
| **Filename** | Monotonic `NNN_snake_description.sql` (3-digit zero-pad; lexical apply order) |
| **Next free N** | **`010`** (after `009_caller_preference.sql`) |
| **History** | Never reuse N; never edit applied files under SoT (or root copies) |

### P2.14-R2 One concern

- One migration file = one concern (create `flow_*` family **or** alter transcript **or** drop desk family — not combined).  
- Aligns with P2.13 **Forbidden** mega-file and P2.0-P10.

### P2.14-R3 Apply + failure

| Fact (inventory) | Locked behaviour |
|---|---|
| `store.Open` → `ApplyMigrations` | Pending files applied in lexical order; each file in one transaction; recorded in `schema_migrations` |
| Migrate / Open error with Postgres URL set | Process **must exit** (refuse to serve) — `cmd/aiorchestrator` already exits on `store.Open` failure |
| `database.require=true` and empty URL | Process **must exit** (no silent memory) |
| Lab memory | URL empty + `database.require=false` → in-memory store; **no** migrate — unaffected |

### P2.14-R4 CI (minimum)

Until Job B lands in `.github/workflows` (none present 2026-09-05 — [11](../11_CI_AND_CD.md)):

| Check | Required |
|---|---|
| `go test ./internal/store/...` including migrate tests | **Yes** at L4 for any migration PR |
| Job B `migrate-empty` (empty Postgres → SoT apply) | **Yes when CI exists** — always-run per [11] Job B; until then **manual lab checklist** on every migration PR |
| Forbidden: merge migration that fails empty apply | **Yes** |

**Manual lab checklist (migration PRs, until Job B):**

1. Empty Postgres + `DATABASE_URL`.  
2. `go test ./internal/store/... -count=1` (incl. integration when URL set).  
3. Confirm `schema_migrations` lists `001`…highest applied.  
4. Fail PR if empty apply errors.

### P2.14-R5 Expand/contract

- Prefer additive NULLable columns → backfill → switch readers → DROP / NOT NULL in a **later** file.  
- Cite P2.0-P10.

### P2.14-R6 Secrets

- Migrations must not insert real API keys or copy `.agent/secrets.local.json` material.

### P2.14-R7 Dual path / obsolete creates

- No migration may **CREATE** (or `IF NOT EXISTS` recreate) `desk`, `desk_draft`, `desk_version`, or treat `kb_*` as the new Inform store.  
- New graph/config tables use `flow_*` / `binding` names only (OD-08-3 / OD-08-4).
