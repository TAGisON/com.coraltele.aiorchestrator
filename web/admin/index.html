Portal Admin Supervisor User

Platform configuration

Nothing is pre-seeded. Configure engines and credentials, publish a contact desk (or a raw profile), then verify readiness before Users start sessions.

Readiness

Abnormal conditions surface here (DB down, engines missing, no profiles, unregistered gateway ids, Sarvam key missing).

    System settings
    
        
    Optional string keys stored in Postgres. Empty until you save. Common keys:
    
        
      
          
    • coral.base_url — base URL for Coral transfer / CRM skill gateways (warm transfer, CRM callbacks). Leave empty if you are not integrating Coral yet.
      • 
          
    • control.auth_token — if set, Control API requires Authorization: Bearer …. Leave empty for open local lab.

    Contact desks
    
      
    A desk is the business-facing configuration: prompts in English and Hindi, intents, guided paths, routing matrix and connectors. Publishing a desk compiles and publishes its behaviour profile automatically — you do not author profile JSON for a desk.

      Connector sandbox
      
      
      The desk-skills connectors run in stub mode until a real CRM or ACD is wired. Force a failure here to rehearse the never-invent rules: a failed ticket must never produce a ticket number, and a failed email must never delete a ticket.

      Behaviour profiles
      
      
      A profile is the session behaviour document (persona, language, clips, skills, voice map). Nothing is pre-seeded in the database — author JSON yourself, then Create + publish. Users pick the profile id when starting a session.
